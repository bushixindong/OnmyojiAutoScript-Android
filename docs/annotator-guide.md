# OAS 标注工具使用指南

给非程序同学看的手册。看完能自己改素材、自己测、自己判断问题出在哪。

---

## 一、这是什么

OAS 自带一个网页版的素材标注工具，用来做一件事：**在游戏截图上框出按钮，它帮你裁图、算坐标、写进代码。**

改素材不用打开代码编辑器，全在浏览器里点完。

---

## 二、怎么打开

### 启动服务

```powershell
cd E:\OnmyojiAutoScript
.\toolkit\python.exe server.py
```

启动后命令行会打出三行 `ready`，分别对应三个服务：

| 服务 | 端口 | 作用 |
|---|---|---|
| 网页主服务 | 22288 | 标注工具本体 |
| 图像识别 | 22269 | 找图 |
| OCR 识别 | 22268 | 认字 |

> 端口取自 `config/deploy.yaml` 的 `WebuiPort`。默认值是 22267，本机改成了 22288。

### 访问地址

```
http://127.0.0.1:22288/tool/annotator
```

### 关闭服务

命令行按 `Ctrl+C`，或者把占用上述端口的进程结束掉。

> 这个工具只在你电脑上跑，**不参与手机端运行**。改界面、改标注方式都不需要重新打包。

| 区域 | 面板 | 干什么 |

## 四、两个核心概念：roiFront 和 roiBack

两个都是框，作用完全不同。

| | 名称 | 框住什么 | 作用 |
|---|---|---|---|
| **roiFront** | 前景框 / 素材区域 | 目标图标**本身** | 这块会被裁成 png，作为比对用的模板 |
| **roiBack** | 背景框 / 搜索范围 | **去哪里找**这个图标 | 只在这块区域里搜索，范围外不找 |

真实例子（`tasks/DailyTrifles/dt/image_pickup_email.json`）：

```json
"roiFront": "337,505,37,25",     // 邮件小图标本身，37×25 像素
"roiBack":  "38,396,1128,157"    // 整个邮件列表区域
```

一句话：**在大范围（back）里找小图标（front）**。

四个数字是 `左上角X, 左上角Y, 宽, 高`。

### back 框的取舍

- 框大 → 找得慢，容易误判（别处长得像的东西也会命中）
- 框小 → 快、准，但游戏界面一变就可能找不到

## 五、素材放在哪

每个任务一个文件夹，素材就近放：

```
tasks/DailyTrifles/                 ← 任务根目录
├── assets.py                       ← 自动生成的代码，别手改
├── dt/                             ← 子模块（邮件）
│   ├── image_pickup_email.json     ← 规则清单（在这里改）
│   └── dt_harvest_mail.png         ← 裁出来的素材图
└── love/                           ← 另一个子模块（好友祝福）
```

- **image.json**：人看的清单，记录每条规则的名称、坐标、算法、门槛
- **assets.py**：机器用的代码，由 json 自动生成（文件头写着 "Don't modify it manually"）

保存规则时，工具会自动重新生成 assets.py，不用手动跑脚本。

---

## 六、规则类型

下拉框里六种，99% 的情况只用前两种。

| 类型 | 用途 | 什么时候用 |
|---|---|---|
| **RuleImage（图片匹配）** | 找图 | 找按钮、图标。最常用 |
| **RuleOcr（文字识别）** | 认字 | 读数字、读文字（"体力 120/200"） |
| **RuleClick（点击坐标）** | 点固定位置 | 没有图标可找，只能死点 |
| **RuleSwipe（滑动）** | 滑动 | 拖拽、翻页 |
| **RuleLongClick（长按）** | 长按 | 按住不放 |
| **RuleList（列表）** | 列表 | 一列/一行多个同款项目（邮件列表、好友列表） |

---

## 七、参数说明

### RuleImage（图片匹配）

| 参数 | 含义 | 建议 |
|---|---|---|
| itemName | 规则名，代码里用它 | 英文小写+下划线，如 `harvest_mail` |
| imageName | 素材文件名 | 自动跟着 itemName 生成，一般不动 |
| method | 匹配算法 | 默认 `Template matching`，见第八节 |
| threshold | 相似度门槛，0~1 | 默认 0.8。调低易认出但易误判，调高更严格 |
| description | 说明 | 写上这按钮是干嘛的，方便以后看 |

### RuleOcr（文字识别）

| 参数 | 含义 | 选项 |
|---|---|---|
| mode | 识别模式 | `Single` 单行 / `Full` 整块 / `Digit` 纯数字 / `DigitCounter` 如 3/10 / `Duration` 时间 / `Quantity` 数量 |
| keyword | 关键词 | 期望识别出的文字，用于判断是否命中 |

### 其它类型

- **RuleClick**：只有规则名和说明，点的是 roiFront 的中心
- **RuleSwipe**：`mode` 选 `default`（按坐标滑）或 `vector`（按向量滑）
- **RuleLongClick**：`duration` 长按毫秒数，默认 1000
- **RuleList**：额外有 `list.name`（列表名）、`list.direction`（`vertical` 竖向 / `horizontal` 横向）、`list.type`（列表项用 `image` 还是 `ocr` 认）

---

## 八、三种匹配算法

| 算法 | 怎么比 | 通俗理解 | 速度 | 项目里用了几条 |
|---|---|---|---|---|
| **Template matching** | 逐像素比对，素材和目标必须一样大 | 拿照片直接对 | 最快 | 2319 条 |
| **Multi-scale** | 把素材缩成 0.6~1.2 倍共 7 档逐档比 | 站远站近都看一眼 | 慢约 7 倍 | 16 条 |
| **Sift Flann** | 提特征点（角、边缘）再配对 | 认五官位置而非比对照片 | 最慢 | 3 条 |

### 怎么选

- **默认用 Template matching**。手机虚拟屏固定 1280×720，素材同分辨率截取，尺寸天然一致
- **Multi-scale**：素材来自别的分辨率，或图标在游戏里会缩放（项目里那 16 条都在"探索"的高亮特效上）
- **Sift Flann**：图标会被旋转、拉斜。注意它**不返回分数**，只看配对成功/失败，调 threshold 无效

> 换算法后必须重新测试，三种算法的分数分布完全不同。

## 九、怎么测试，怎么判断能不能认

选中一条规则 → 点「测试」，会发生两件事。

### 1. 画面上出现两个虚线框

| 框 | 颜色 | 含义 |
|---|---|---|
| 素材位置 | 蓝色虚线 | 实际找到的位置（**不一定在原处**） |
| 搜索范围 | 青色虚线 | 你的 roiBack 范围 |

如果蓝框偏了或套错东西，说明素材本身有问题。

### 2. 中间底部打印结果

```json
"similarity": 0.8944,    // 相似度得分 0~1
"matched": false,        // 是否命中
"threshold": 0.9,        // 门槛
"message": "not_match"   // 结论
```

**判断规则：`相似度 ≥ 门槛` 才算能认。**

| 相似度 | 门槛 0.8 时 | 说明 |
|---|---|---|
| 0.90 以上 | 能认 | 素材干净 |
| 0.80~0.90 | 能认 | 正常水平 |
| 0.70~0.80 | 认不出 | 差一点，重裁素材或降门槛 |
| 0.50 以下 | 认不出 | 素材不对，重新框 |

### message 的含义

| message | 意思 | 怎么办 |
|---|---|---|
| `match` | 命中 | 没问题 |
| `not_match` | 没找到，分数不够 | 降门槛或重裁素材 |
| `roi_back_too_small` | 搜索范围比素材还小 | 把 roiBack 框大 |
| `image_load_failed` | 素材图坏了 | 重新裁剪 |
| `sift_error` | Sift 算法出错 | 换回 Template matching |

### 小技巧

- 测完按钮变成「清除」，再点一次清掉虚框
- OCR 测试结果里会多一个 `text` 字段，是它**真正读出来的字**。读错字说明框的位置或识别模式要改

## 十、怎么更新一张已有素材

先分清情况：

| 情况 | 做什么 |
|---|---|
| 只是图标换了样子，位置没动 | 换 png，不保存坐标 |
| 位置或大小也变了 | 换图 + 保存坐标 |

### 步骤

1. 左侧「来源」→ 连接模拟器 或 上传截图 → 点「截取当前帧到图片列表」
2. 右侧「文件」→ 按目录选到任务的 json
3. 右侧「规则」→ 搜索框输入 itemName → 点中那一条
4. 中间画面上重新框 roiFront
5. 点 **「裁剪」** → 用新图覆盖原 png
6. 位置变了就点 **「保存」** → 写回坐标并重新生成 assets.py
7. 点 **「测试」** 验证

## 十一、常见问题

### 误操作了，怎么撤销

**工具本身没有撤销键。** 唯一可靠的后悔药是 git：

```bash
cd E:\OnmyojiAutoScript
git status                      # 看哪些文件被改了
git checkout -- 文件路径          # 还原单个文件
```

建议：动手前先提交一次（`git add -A && git commit -m "素材快照"`），之后怎么改都能退回来。

### 点了保存但没生效

检查三点：

1. 是否点的是「保存」而不是「裁剪」（裁剪只改图片，不写坐标）
2. 后端是否报错（看命令行窗口）
3. 是否改的是另一个 json（同一任务可能有多个子模块的 json）

### 测试分数一直在 0.7 左右

说明素材与当前画面有差异，常见原因：

- 素材是旧版本游戏截的图 → 重裁
- 截图分辨率与素材来源不同 → 检查模拟器分辨率是否 1280×720
- 素材裁得太大，把背景也带进去了 → 框小一点，只框核心图案

### 门槛能调多低

不建议低于 0.75。搜索范围特别小（如 60×60 以内）时，降到 0.85 基本安全；范围很大时保持 0.8~0.9。

## 十二、改完之后

素材文件在 `E:\OnmyojiAutoScript\tasks\<任务>\` 下，属于**引擎代码**。让它上手机要三步：

1. 提交到引擎仓库的 `fix/v1.0.4` 分支
2. 重新导出运行时包（把脚本打包进 App）
3. 装新 APK 或走热更新

**第 2 步最容易忘**：代码改了、推了，手机里跑的还是旧素材。

## 附录：新增一个任务，我需要提供什么

不需要懂代码结构，按下面这份"任务卡片"填就行。

### 任务卡片模板

```
【任务名称】游戏里叫什么？（如：御魂副本、年兽）

【从哪开始】打开任务时，游戏应该停在哪个界面？
            （如：庭院主界面 / 探索页面）

【操作步骤】按顺序写，每一步说明"看到什么 → 点什么"
            1. 看到XX按钮 → 点它
            2. 进到XX界面 → 等出现YY → 点YY
            3. ...
            （有循环就写"重复以上第2-5步，直到XX"）

【结束条件】什么情况算做完？
            （如：体力用完 / 奖励领完 / 打满3次）

【配置项】玩家需要自己选的东西有哪些？
            （如：打哪个难度、用哪套阵容、打几次）

【异常情况】遇到这些情况怎么办？
            - 体力不够时：
            - 战斗失败时：
            - 弹窗挡住时：
            - 找不到按钮时：

【截图】每个步骤对应界面的截图，标出要点的地方
```

### 怎么知道自己该准备什么

最实用的办法：**开着标注器，自己手动玩一遍这个任务**，一边玩一边截图。

- 每到一个新界面，截一张 → 这就是"操作步骤"里的一步
- 每个要点的按钮，在图上圈一下 → 这就是需要做的素材
- 每次犹豫"这里要不要点"，把判断依据写下来 → 这就是"异常情况"

玩完一遍，你手上就是一套完整的流程图 + 截图，这些就是开发任务需要的全部输入。

### 任务做出来大概长什么样

```
tasks/任务名/
├── script_task.py      ← 主流程（按你说的步骤编排）
├── config.py           ← 配置项（你说的"玩家要选的"）
├── assets.py           ← 素材清单（自动生成）
└── 子模块/              ← 素材图片和规则 json
```

不需要你写这些，你把上面的卡片填好就行。
